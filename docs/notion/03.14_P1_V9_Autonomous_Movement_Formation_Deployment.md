# 03.14 — Experimental Variant P1-V9 — Autonomous Movement & Formation Deployment

> **Status:** Experimental · implemented in Phaser code · verification pending. Triggered after P1-V8 verification. Goal: make the formation grid define deployment/spawn positions while Battle units move and act autonomously instead of remaining locked to cells. Not adopted into Current Gameplay Spec.
## Design Intent
Battle Setup remains a tactical deployment phase.
- Grid communicates where each unit starts.
- Start Battle locks deployment.
- At Battle start, units spawn from those positions.
- The grid fades away.
- Units then acquire targets, move, attack, retreat/reposition where appropriate, and retarget autonomously.
Formation should matter because it changes **starting distance, protection, lane access, and time-to-contact**, not because Battle units remain attached to cells.
## Experimental Battle Loop
Per deterministic 1.0s combat tick:
1. Acquire / retain a target.
2. Measure distance.
3. Move / retreat OR attack.
4. Apply damage.
5. Resolve deaths.
6. Reacquire when target is gone.
## Prototype Combat Space
Use model-space coordinates independent from Phaser pixels.
- Player Back / Mid / Front spawn depth: x = -3 / -2 / -1.
- Center line: x = 0.
- Enemy Front / Mid / Back spawn depth: x = +1 / +2 / +3.
- Formation lane 1–6 maps to y = 1–6.
- Movement may interpolate continuously between these positions.
## Role Movement Identity
### Tanker
- Melee.
- Moves toward the nearest frontline enemy.
- Holds contact once in melee range.
- Front deployment reaches contact faster and naturally becomes the frontline.
### Assassin
- Melee / fast movement.
- Targets the deepest suitable living enemy.
- Moves/dashes through open combat space without body-block simulation.
- Reacquires another deep target after a kill.
### Ranger
- Ranged.
- Uses a preferred safe range.
- If too far: advances.
- If inside safe range: attacks.
- If enemy is too close: retreats toward the player side before attacking again.
- Back deployment should naturally gain more attack uptime than Front deployment without a row damage multiplier.
### Mage
- Ranged / area pressure.
- Uses a preferred range.
- Moves into range when too far and retreats only when pressured too closely.
- Retains Arcane Burst identity when attacking.
### Enemy Squad
- No complex enemy roles in V9.
- Each living enemy moves toward the current player frontline and attacks only when in melee range.
- No pathfinding/body blocking/navmesh in this prototype.
## Presentation
- Battle begins with the deployment grid visible briefly (\~0.5–1.0s).
- Grid fades away while units begin autonomous movement.
- Unit/enemy visuals interpolate to model positions.
- Attack / hit / death / heal feedback remains.
- Assassin / ranged / Mage visuals must follow their actual model targets.
## P1-V8 Relationship
- Keep V8 target identity:
	- Tanker frontline target.
	- Assassin deep target.
	- Ranger deep same/near-lane target.
	- Mage lane burst.
- Replace V8 Ranger/Mage row damage multipliers with movement/range consequences in V9.
- Historical V8 rules remain available as regression evidence.
## Preserved Rules
- P1-V7 enemy fixture / battle-duration pressure baseline.
- 1.0s deterministic tick.
- Existing base role stats and STAR multipliers.
- Stored finite Energy and +30 Frontline Heal.
- BattleSetup formation lock.
- Result → Restart.
- P1-V9 remains Experimental.
## Non-Goals
- No navmesh.
- No collision/body blocking.
- No knockback.
- No active skill buttons.
- No mana/cooldowns/status effects.
- No production animation system.
- No final movement/balance values.
