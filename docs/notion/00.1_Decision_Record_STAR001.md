# 00.1 — Decision Record — STAR-001 Queue → Star Conversion

> **Decision status:** Adopted (đã chấp nhận). STAR-001 is now part of the Current Gameplay Spec baseline at **1 / 3 / 9**.
**Parent rule:** STAR-001 — define one consistent Queue → 1★ / 2★ / 3★ economy.

Because QUEUE-001 currently defines **one successful Beast match = +1 queue count**, these two paths produce different combat value from the same puzzle performance.
## Design Goal
The conversion rule should preserve a readable causal chain:
**Valid Beast Match → Queue Growth → Deployment Choice → Visible Combat Power**
The player should be able to understand what one additional Beast match is worth before entering combat.
## Option A — 1 / 3 / 9
**Rule**
- 1 queue count → 1★
- 3 queue counts → 2★
- 9 queue counts → 3★
**Expected strengths**
- One successful Beast match can become one visible 1★ unit.
- Easy mental model: three lower-tier units equal one higher-tier unit.
- Matches the current individual-deploy behavior.
- Strong Match → Reward readability.
**Trade-offs (đánh đổi)**
- Army generation is relatively generous.
- Star scaling is already large in the current prototype, so higher tiers may become available too quickly.
- Requires later tuning of unit power or preparation throughput.
## Option B — 2 / 6 / 18
**Rule**
- 2 queue counts → 1★
- 6 queue counts → 2★
- 18 queue counts → 3★
**Expected strengths**
- Slower army growth.
- Gives the Combo window more importance because multiple matches are needed before combat value appears.
- Can reduce unit count on the battlefield.
**Trade-offs (đánh đổi)**
- A single valid Beast match may produce no deployable unit.
- Weaker immediate Match → Consequence readability.
- Harder to explain why the queue increases by 1 but a 1★ unit costs 2.
## Option C — Separate Queue Unit from Match Count
Instead of treating one queue count as one match result, redefine the stored resource.
Example:
- valid Beast match grants +2 Beast fragments,
- 2 fragments → 1★,
- 6 fragments → 2★,
- 18 fragments → 3★.
This makes the 2 / 6 / 18 hierarchy internally consistent, but changes QUEUE-001 and adds an extra resource abstraction.
**Trade-off:** technically consistent, but introduces more terminology and cognitive load for little prototype value.
## Adopted Decision (quyết định đã chấp nhận)
Option A — **1 / 3 / 9** is the current design baseline and the first rule to validate.
Reason:
- one Beast match has an immediately understandable value,
- the 3-to-1 hierarchy is easy to communicate,
- it preserves the current manual deployment behavior,
- balance can later be controlled through Combo duration, Beast stats, wave pressure and star multipliers.
This rule has been adopted into the Current Gameplay Spec. It is still **Needs Validation (cần kiểm chứng)** for army growth, star frequency and deployment behavior.
## What to Validate
If Option A is tested:
- How many 1★ / 2★ / 3★ units does a typical preparation phase create?
- Does the player understand the upgrade relationship without explanation?
- Is there a meaningful reason to deploy now versus save queue value?
- Does 3★ appear too frequently under current Combo timing?
- Does battlefield readability suffer from too many 1★ units?
