# 02.5 — P1-S0 Implementation Task — State Migration

> **Active implementation task.** Execute only after the project-root `AI_INSTRUCTIONS.md` has been synchronized to the P1 source order.
**Design Source:** <mention-page url="https://app.notion.com/p/3ec2674d32c3812296a8de866c65c434"/>

**Implementation Matrix:** <mention-page url="https://app.notion.com/p/3ec2674d32c381919709d2b17efb3f57"/>
## Goal
Migrate only the Phaser phase/state structure toward P1.
Target phase graph:
```plain text
BeastRush
→ EnergyRush
→ BattleSetup
→ Battle
→ Result
```
This slice is a **state migration**, not the Energy Queue, formation, autonomous-combat or skill redesign slice.
## Required Work
1. Inspect the current `GamePhase`, `PhaseController` and `ValidationScene` flow before editing.
2. Introduce the P1 phase names / transition graph.
3. Map the old P0 phase responsibilities to compatibility hooks only where necessary.
4. Update visible phase labels so the browser can show each P1 state.
5. Preserve the existing Onet board, matcher, deadlock and STAR-001 logic.
6. Preserve Result / Restart behavior.
7. Add deterministic checks for legal/illegal P1 phase transitions.
8. Update the Phaser Implementation Matrix after verification.
## Explicit Non-Goals
Do **not** implement in P1-S0:
- EnergyQueue,
- Energy match → stored charge conversion,
- Beast role stats,
- battlefield slots,
- drag/drop arrangement,
- autonomous HP/DPS combat,
- new Energy skill,
- mid-combat reposition,
- new validation metrics.
Those belong to later P1 slices.
## Compatibility Rule
Existing P0 systems may remain temporarily behind the new state graph if removing them would require P1-S1+ work.
However:
- do not claim the old behavior is synchronized,
- do not change Current Gameplay Spec v2 to match the old code,
- mark transitional behavior clearly.
## Deterministic Checks
Minimum:
- initial phase = BeastRush,
- BeastRush → EnergyRush allowed,
- EnergyRush → BattleSetup allowed,
- BattleSetup → Battle allowed,
- Battle → Result allowed,
- Result → BeastRush restart allowed,
- invalid skips/reverse transitions rejected unless explicitly required by the current spec,
- restart still clears the current validation session state expected by P0-compatible systems.
## Build / Live Verification
After code changes:
1. run relevant existing regression checks,
2. run new P1-S0 transition checks,
3. run production build,
4. open browser and verify phase labels / transition order,
5. report any temporary P0 compatibility behavior still present.
## Exit Gate
P1-S0 is complete only when:
- [ ] transition graph is implemented,
- [ ] deterministic transition checks pass,
- [ ] relevant P0 regression checks still pass,
- [ ] production build passes,
- [ ] browser visibly follows the P1 state order,
- [ ] no P1-S1+ feature was silently added,
- [ ] Phaser Implementation Matrix is updated.
After this gate, stop and review before starting P1-S1.
