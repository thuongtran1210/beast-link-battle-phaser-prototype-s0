## Objective
Implement the first real tactical decision layer before Battle:
**Beast Queue → STAR conversion → role-readable units → player arrangement → Start Battle**.
P1-S2 does not implement autonomous combat yet. It only proves that the player can understand the army they rolled and deliberately place units before Battle.
## Experimental Role Mapping
Current Gameplay Spec adopts the role vocabulary but not placeholder-ID mapping.
For P1-S2, use this **Experimental / prototype-only fixture** for the current placeholder Beast IDs:
- beast-a → Tanker
- beast-b → Assassin
- beast-c → Ranger
- beast-d → Mage
- beast-e → Tanker
- beast-f → Ranger
This mapping is not an adopted production content rule.
## Role Presentation
Every converted unit shown in BattleSetup must display at least:
- Beast display ID / letter
- Role
- Star tier
Example validation label:
`A · Tanker · 2★`
Do not add final role stats yet.
## STAR Conversion
- Use the existing STAR-001 converter unchanged: 1 / 3 / 9.
- Convert the remaining BeastQueue once when entering BattleSetup.
- Preserve Beast identity.
- Each produced star unit becomes one arrangeable unit record.
- Do not invent an alternate deploy path in P1-S2.
## Formation Model
Create a small pure model, e.g. `BattleFormation`, with:
- unitId
- beastId
- role
- star
- slotId \| null
Required behavior:
- every converted unit exists exactly once,
- one slot can contain at most one unit,
- a unit can occupy at most one slot,
- placing a unit in an empty slot succeeds,
- moving a placed unit to another empty slot succeeds,
- swapping two occupied slots may be supported if simpler, but is not required,
- reset clears placement state.
## Experimental Battlefield Layout
Use a **3-row × 6-column validation grid (18 slots maximum)**:
- Front row
- Mid row
- Back row
Why this fixture:
- a 6×6 Beast board has at most 18 successful pair matches,
- therefore 18 slots avoid inventing an army-cap rule,
- three labeled rows make positional intent readable before combat exists.
This topology is **Experimental / prototype-only**, not an adopted final battlefield layout.
## Role Guidance
Provide readable positional guidance only; do not add combat bonuses yet:
- Tanker → Front recommended
- Assassin → Front / Mid recommended
- Ranger → Back recommended
- Mage → Back recommended
Recommended rows are UI guidance, not placement restrictions. The player may place any role in any slot.
Do not give hidden bonuses or penalties in P1-S2.
## BattleSetup UI
Replace the minimal setup shell with a validation-oriented arrangement screen.
Required sections:
1. **Unplaced Units** — cards/list of converted units.
2. **Formation Grid** — Front / Mid / Back rows with slot labels.
3. **Stored Energy** — keep P1-S1 read-only summary.
4. **Start Battle**.
Recommended interaction:
- click a unit card to select it,
- click a slot to place/move it.
Drag-and-drop is not required.
`Start Battle` must be disabled until every converted unit has a valid slot.
If zero units exist, do not invent a fallback army. Keep Start Battle disabled and surface a validation/debug message.
## Battle
- No puzzle board/input.
- Carry the exact chosen formation into Battle.
- Display formation read-only so persistence is visually verifiable.
- Keep Stored Energy read-only.
- Keep prototype-only `Complete S0 Battle` action.
- Do not add autonomous combat or role stats yet.
## Restart
- Clear formation state.
- New run must not inherit unit placement.
- BeastQueue and EnergyQueue reset behavior must remain correct.
## Deterministic Checks
Add P1-S2 checks for:
1. experimental Beast ID → role mapping is deterministic,
2. STAR-001 conversion remains 1 / 3 / 9,
3. converted units preserve beastId + role + star,
4. each converted unit has a unique unitId,
5. new formation starts with all units unplaced,
6. placing a unit occupies exactly one slot,
7. duplicate occupancy is rejected,
8. moving a unit clears its previous slot,
9. recommended row does not block off-role placement,
10. Start Battle is disabled while any unit is unplaced,
11. Start Battle is enabled when all units are placed,
12. chosen formation survives BattleSetup → Battle unchanged,
13. Stored Energy survives unchanged,
14. Battle remains puzzle-free,
15. Restart clears formation, BeastQueue and EnergyQueue per-run state,
16. P1-S0 and P1-S1 checks remain green,
17. relevant Onet / deadlock / STAR regressions remain green.
## Visible UI Check
BattleSetup should make it possible to answer at a glance:
- What units did I get?
- What role is each unit?
- What star tier is each unit?
- Where did I place each unit?
- How much Energy am I bringing into Battle?
Battle should show the same formation read-only.
## Forbidden in P1-S2
Do not implement:
- HP / Damage / Attack Speed role stats,
- target selection,
- autonomous combat ticks,
- enemy attacks,
- Win/Lose,
- Energy consumption,
- Heal / Shield / Damage skills,
- role bonuses from row placement,
- mid-combat reposition,
- final battlefield topology decision,
- final Beast content mapping,
- waves / meta / progression.
## Verification
After implementation:
1. run `npm.cmd run check`,
2. run `npm.cmd run build`,
3. live-browser verify:
	- create at least 2 converted Beast units,
	- confirm role + star labels,
	- Start Battle disabled before full placement,
	- place all units across at least two different rows,
	- confirm Start Battle enables,
	- enter Battle,
	- confirm same formation is displayed read-only,
	- confirm Stored Energy unchanged,
	- confirm no puzzle board exists,
	- Restart and confirm placement state is cleared.
