# 01.1 — Repo Stabilization Checklist

> **Purpose:** stabilize only the Unity implementation needed to keep repository evidence trustworthy. This is not a polish roadmap and does not require finishing the full game.
**Parent source:** <mention-page url="https://app.notion.com/p/3ec2674d32c3811da2f7dc1c6528cb9b">01 — Unity Implementation Audit</mention-page>  
**Design source:** <mention-page url="https://app.notion.com/p/3ec2674d32c3812296a8de866c65c434"/>
## Priority Model
- **Critical (cần xử lý trước):** current Unity state conflicts with a gameplay rule or makes the main flow unreliable / ambiguous.
- **Should Fix (nên xử lý):** does not block the core design story, but weakens implementation credibility or future maintenance.
- **Can Defer (có thể hoãn):** outside the portfolio-critical slice; keep documented but do not spend time now.

## Can Defer
- Full shop / economy balancing.
- Final enemy roster balancing.
- Production art replacement.
- Full animation / VFX polish.
- Additional bosses or grid-disruption mechanics.
- PvP / Rogue-lite modes.
- Final retention / monetization systems.
- Auto-skill expansion for every Beast.
- Refactoring unused legacy configs unless they create active confusion.
- Full automated test coverage.
These can remain outside the portfolio-critical slice as long as they are not presented as finished features.
## Recommended Fix Order
1. **STAR-001** — sync ResolveBattlePhase() to the adopted **1 / 3 / 9** design rule.
2. **FLOW-001 scene/build entry** — make the current project entry path deterministic.
3. **DEADLOCK-001** — wire automatic puzzle safety.
4. **ENERGY-003 HUD initialization** — make the battle-support phase evidence reliable.
5. Align Combo defaults.
6. Clean Level / Enemy serialization drift.
7. Verify enemy spawn timing.
8. Clean one representative Wave/Level data set.
## Definition of Stable Enough for Portfolio
The Unity repo does **not** need production polish. It is stable enough when:
- [ ] Current entry scene reaches the intended current gameplay flow.
- [ ] STAR-001 has one consistent rule.
- [ ] Deadlock recovery is connected to the normal puzzle flow.
- [ ] Energy gauges initialize from the selected deck.
- [ ] Current Gameplay Spec Rule IDs used in the portfolio are either **Synced** or intentionally marked **Needs Sync / Conflict**.
- [ ] No recruiter-facing claim depends on obsolete serialized fields.
- [ ] One representative level/wave configuration is readable enough to inspect.
- [ ] Unity art quality is not treated as final visual quality.
## Update Rule
When a task above is completed:
1. Update the relevant row in **Unity Implementation Audit**.
2. Change Sync Status to **Synced** only when Unity matches the Current Gameplay Spec.
3. Do not change Current Gameplay Spec for a technical fix.
4. If the fix requires a gameplay-rule decision, resolve that decision in the Spec first.
