# 03.15 — Experimental Variant P1-V10 — Showcase UI / Capture Mode

> **Status:** Experimental · implemented in Phaser code · verification pending. Presentation-only layer for screenshots/showcase. Must not change P1-V9 combat rules or validation evidence behavior when Showcase Mode is OFF. Not adopted into Current Gameplay Spec.
## Goal
Provide a clean presentation layer for screenshots, demo frames, README/Notion showcase, and pitch material without replacing the validation/debug UI.
## Modes
### Validation Mode
- Existing validation UI remains available.
- Full diagnostic text / technical status remains visible.
- Used for P03/P04/P05 evidence collection.
### Showcase Mode
- Cleaner top/header treatment.
- Compact Battle HUD.
- Compact Stored Energy rows with visible Heal actions.
- Reduced technical text.
- Pause/Resume capture control.
- Clean Frame control to hide capture chrome.
- No gameplay-rule changes.
## Controls
- F1: Toggle Validation / Showcase Mode.
- Space: Pause / Resume Battle while in Showcase Mode.
- H: Hide / Show capture-control chrome.
- On-screen buttons mirror these actions.
## Showcase Battle HUD
Must show:
- Battle status / tick.
- Enemy squad living count + aggregate HP.
- Current frontline Beast + HP.
- Stored Energy total.
- Compact Energy rows: `ENERGY-X · N [HEAL]`.
- Every Heal action must remain visible/clickable within 960×760.
Must hide/reduce:
- long validation explanation paragraphs,
- repeated technical copy,
- debug-only terminology not useful in a screenshot.
## Capture Behavior
- Pausing freezes Battle model ticking only; it does not mutate combat state.
- Resume continues from the same state.
- Clean Frame hides capture controls only; gameplay HUD stays visible.
- Showcase Mode can be toggled off at any time to return to Validation Mode.
## Non-Goals
- No final production HUD.
- No final art.
- No screenshot file export requirement.
- No change to P1-V9 movement, targeting, damage, Heal amount, Energy consumption, state graph, or balance.
