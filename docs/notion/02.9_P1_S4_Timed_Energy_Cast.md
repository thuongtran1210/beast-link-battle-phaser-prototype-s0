## Objective
Turn Stored Energy from a read-only resource into a **finite timing decision during autonomous Battle**.
P1-S4 must answer:
**Is there a meaningful reason to cast now versus save a charge for later?**
Do not add a second skill in this slice.
## Experimental Skill Fixture
For P1-S4 only, all stored Energy IDs temporarily map to the same validation skill:
**Frontline Heal**
- consume exactly 1 stored charge from the selected Energy ID,
- heal the current front-most alive player unit by **+30 HP**,
- healing is capped at that unit's max HP,
- defeated units cannot be revived,
- if no player unit is alive, cast is rejected,
- cast is allowed only while Battle status = Running.
Status: **Experimental / prototype-only fixture**.
Reason for this fixture:
- casting at or near full HP wastes healing,
- waiting allows more value,
- waiting too long can let the current frontline unit die,
- therefore timing can matter without adding targeting UI or multiple skills.
Do not update Current Gameplay Spec with +30 HP unless this variant is later adopted.
## EnergyQueue Consumption
Extend `EnergyQueue` with safe consumption behavior:
- `tryConsume(energyId, amount = 1)` or equivalent,
- reject if insufficient charges,
- never allow negative charges,
- preserve independent counts per Energy ID.
Consumption must affect only the selected Energy ID.
## Battle UI
Keep autonomous combat exactly as P1-S3.
Add a small Stored Energy interaction area:
- show each Energy ID + remaining charges,
- for IDs with charges \> 0, provide a `CAST HEAL` action tied to that ID,
- disable/reject cast if charge count = 0,
- show the current frontline target and current/max HP so timing is readable.
Example:
`Frontline: C · Ranger · 15 / 45 HP`
`energy-c: 2   [CAST HEAL]`
No puzzle board. No manual formation edits.
## Cast Resolution
When a valid cast occurs:
1. verify Battle status = Running,
2. verify selected Energy ID has at least 1 charge,
3. identify current front-most alive unit using the same Front → Mid → Back / stable-slot ordering as enemy target priority,
4. consume 1 selected Energy charge,
5. apply +30 HP capped at max HP,
6. update Battle + Stored Energy UI immediately,
7. autonomous ticks continue normally.
Do not pause Battle permanently for a cast.
## Timing Expectations
The skill should visibly support these cases:
- cast at full HP → charge consumed but most/all heal wasted,
- cast after damage → useful recovery,
- cast just before a potentially lethal future tick → may extend frontline survival,
- wait until that unit is already defeated → cannot revive it; heal applies to the next current frontline if one exists.
Do not add critical hits, status effects, cooldowns, cast animations, or multiple targets.
## No-Cast Path
Battle must still progress and reach Win/Lose if the player never casts.
This is mandatory. Energy is an intervention, not the engine that advances Battle.
## Result
Result should preserve at least:
- Battle Outcome,
- remaining Stored Energy counts/total if already easy to expose.
Do not redesign final P1 metrics yet; P1-S5 handles instrumentation.
## Deterministic Checks
Add P1-S4 checks for:
1. EnergyQueue consumption removes exactly 1 from selected ID,
2. insufficient-charge consume is rejected with no mutation,
3. other Energy IDs remain unchanged,
4. cast rejected when Battle is not Running,
5. cast rejected when no charge exists,
6. cast at full HP caps at max and still consumes one charge,
7. damaged frontline receives +30 capped at max,
8. defeated units are never revived,
9. current front-most alive unit uses Front → Mid → Back / stable slot order,
10. if old frontline is dead, cast affects the next alive frontline,
11. cast does not mutate formation slots,
12. cast does not pause/stop autonomous ticks,
13. no-cast battle still reaches terminal Win/Lose,
14. at least one deterministic fixture shows that a correctly timed heal changes survival duration or Battle outcome/state versus no-cast baseline,
15. Stored Energy count persists correctly into Result,
16. Restart clears EnergyQueue and combat state,
17. P1-S0/S1/S2/S3 and reusable Onet/deadlock/STAR checks remain green.
## Live Verification
Use one run with at least 2 stored charges if possible.
Verify:
1. Start Battle and do not cast immediately.
2. Observe frontline HP decrease autonomously.
3. Cast once after meaningful damage.
4. Confirm HP rises by up to 30 and exactly one selected Energy charge disappears.
5. Let Battle continue automatically.
6. Optionally cast a second charge at a different timing.
7. Confirm Result is still reached automatically.
8. Confirm no puzzle board appears.
If practical, compare:
- early/full-HP cast,
- delayed damaged-frontline cast.
This comparison is only implementation/timing evidence, not a balance conclusion.
## Forbidden in P1-S4
Do not implement:
- more than one skill effect,
- final Energy-ID → skill mapping,
- manual target selection,
- skill cooldowns,
- animations/VFX polish,
- damage skill,
- shield skill,
- status effects,
- mid-combat formation edits,
- new enemies/waves,
- final balance tuning.
