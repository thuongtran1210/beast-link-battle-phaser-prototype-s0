# 02.11 — P1 Exit Audit — Structural Prototype

> **Purpose:** audit the completed P1 structural prototype before starting real-player validation. This page separates verified implementation evidence, owner-accepted closure, open design decisions, and non-blocking debt.

**Audit date:** 2026-10-01
## Audit Status
**P1-S0 through P1-S5 are closed.**
P1 now implements the intended structural loop:
**Beast Rush → Energy Rush → Battle Setup / Beast Arrangement → Autonomous Battle + Timed Energy Cast → Result → Restart**.
This audit does not claim player validation. It checks whether the prototype is coherent enough to begin that validation.
## Structural Evidence
- BeastRush fills BeastQueue.
- EnergyRush fills EnergyQueue before Battle.
- Both queues persist into BattleSetup.
- STAR-001 1 / 3 / 9 converts Beast output.
- Role-readable units can be arranged on a 3×6 experimental formation grid.
- Battle progresses with zero player input.
- Enemy targeting creates visible formation consequence through Front → Mid → Back priority.
- Battle can terminate automatically in Win / Lose at the model level.
- Stored Energy can be consumed during Battle.
- Experimental Frontline Heal creates an observable timing window.
- Result instrumentation records P1-specific collection / setup / battle metrics in implementation.
- Restart logic clears per-run P1 state in implementation.
## Experimental Fixtures Still Not Adopted
- Energy conversion: 1 valid Energy pair → +1 charge.
- Placeholder Beast ID → role mapping.
- 3×6 formation topology.
- Role HP / Damage values.
- Star combat multipliers.
- Enemy HP / Damage fixture.
- 1-second battle tick.
- Frontline Heal +30 HP.
- All Energy IDs temporarily mapping to the same Heal skill.
These are test fixtures, not production balance decisions.
## Open Design Decisions
- Final EnergyRush termination rule.
- Final Energy match → charge conversion.
- Final role/content mapping.
- Final formation topology and whether mid-combat reposition exists.
- Final skill set and Energy-ID → skill mapping.
- Whether BeastRush Combo values remain 5.0 / +0.3 / 5.0.
- Final combat balance / targeting / wave structure.
## Verification Debt
- P1-S5 was closed by explicit project-owner sign-off.
- `npm.cmd run check` and `npm.cmd run build` had passed before the final small P1-S5 check-file addition; a final rerun after that addition was not separately recorded before closure.
- Clean live Result + Restart proof for the new P1 Session Summary was not separately captured before closure.
These items must not be described as independently verified evidence unless rerun later.
## UI Debt
- BattleSetup has had spacing/overlap regressions around Stored Energy, Unplaced Units, and Start Battle.
- Subtitle/version labeling has occasionally lagged behind the active slice.
Treat these as readability cleanup, not gameplay findings.

- [x] role-readable formation exists,
- [x] autonomous Battle exists,

- [x] P1 instrumentation exists,
- [x] P1 playtest protocol is updated from the old P0 wording,

- [x] main validation round is explicitly started.
## Audit Conclusion
**Implementation structure is sufficient to move from prototyping into P1 validation preparation.**
This is not evidence that the design is good, balanced, or understandable to players. The next work should update the playtest protocol/session template to the P1 loop, then run real-player sessions without changing the baseline during the round unless a severe blocker prevents meaningful testing.
